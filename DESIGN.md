# REA Desktop Design

## Direction

REA Desktop is a **local investigation desk**: a dark, instrument-like workspace that makes the next safe analysis step obvious without pretending that every provider is available. It deliberately refuses the generic dashboard pattern of equal metric cards and instead leads with a target, readiness, and evidence.

## Visual world

- **Scene:** Windows desktop software used during focused technical investigation, often beside a terminal, debugger, or file browser.
- **Palette:** Midnight blue surfaces, steel-blue rules, copper for action and unresolved setup, cyan for active paths, green for verified readiness, and violet for provider-specific signals.
- **Materials:** Quiet panels with thin technical rules, dashed intake boundaries, small mono labels, and restrained signal-like linework.
- **Typography:** DM Sans for readable UI hierarchy and IBM Plex Mono for paths, state labels, and measurement-like metadata.

## Composition

The persistent left rail anchors workspace navigation. The first screen is a split desk: target intake on the left, provider readiness on the right, then recent work and the evidence signal below. Secondary surfaces reuse the same rail and replace the work area with a single clear task.

## Interaction

Primary actions are explicit and keyboard-visible. Native file selection is used for target intake. Provider state is descriptive rather than decorative. Motion stays short and functional, with reduced-motion support for users who prefer it.

## States

Target intake supports empty, selected, and staged states. Providers expose ready, setup-needed, and unknown states. Investigation history exposes complete, active, and paused states. Evidence distinguishes observed, derived, and unknown facts.
